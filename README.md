# Threat vs. Vulnerability 

A simple comparison between "Threat" and "Vulnerability" in cybersecurity.

## 1. Core Definitions & Analogies

1) **Threat:**
  - **Definition:** Anything (person, event, or condition) that can potentially cause harm by exploiting a weakness in a system.
  - **Simple Analogy:** It’s the danger which is the external thing that could happen to cause damage.
2) **Vulnerability:**
  - **Definition:** A weakness or flaw in a system that can be exploited by a threat to cause harm.
  - **Simple Analogy:** It’s the weak spot that makes an attack possible.


## 2. Scenario Example

1) **Threat**
  - **Phishing Attack:** An employee receives a fake email from "HR" asking to verify login details via a link. (Reasoning: Phishing is an external malicious attempt to trick a user.)
  - **Distributed Denial of Service (DDoS):** A hacker uses a botnet to flood a website with traffic until it crashes. (Reasoning: DDoS is an active external attack.)

2) **Vulnerability**
  - **Outdated Software:** A company server runs Windows Server 2012, which no longer receives security update. (Reasoning: Unpatched software creates weakness that could be exploited.)
  - **Misconfiguration:** A firewall is misconfigured to allow all inbound traffic. (Reasoning: A weak configuration that is just waiting to be exploited.)


## 3. How They Work Together
In cybersecurity, a risk only materializes when a **threat** successfully targets and exploits a **vulnerability**. Identifying vulnerabilities (through vulnerability assessments) helps organizations patch their weak spots before a threat actor can take advantage of them.
